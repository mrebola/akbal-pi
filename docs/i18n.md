# i18n — traducciones del admin web (ES/EN)

Sistema centralizado de traducciones para `app/web/admin/` (sin build step,
igual que el resto del frontend): un motor chico (`i18n.js`) + dos
diccionarios JSON (`i18n/es.json`, `i18n/en.json`), con detección de idioma
del navegador, persistencia de la preferencia manual, y un selector siempre
visible en el topbar.

## Cómo funciona

- **`web/admin/i18n.js`**: se incluye antes que el script propio de cada
  página. Al cargar:
  1. Si ya hay un idioma guardado (`localStorage["akbal_lang"]`), lo usa —
     la selección manual siempre gana sobre el idioma del navegador.
  2. Si no, detecta `navigator.languages`: `es` → español, `en` → inglés,
     cualquier otro → inglés por default (spec).
  3. Descarga `i18n/<locale>.json` (+ el de `en` como fallback de claves
     faltantes) y aplica las traducciones al DOM.
- **Aplicación al DOM** vía atributos, sin tocar la estructura existente:
  - `data-i18n="clave"` → `textContent`
  - `data-i18n-html="clave"` → `innerHTML` (solo para strings de diccionario
    con HTML de confianza escrito a mano, p. ej. un `<strong>` de énfasis —
    nunca para datos de usuario/dispositivo)
  - `data-i18n-placeholder` / `data-i18n-title` / `data-i18n-aria-label` /
    `data-i18n-alt` → el atributo correspondiente
- **Selector de idioma**: `<div class="plx-toggle lang-toggle" id="lang-toggle">`
  con dos `<span data-lang="es">`/`<span data-lang="en">` — mismo lenguaje
  visual que el toggle LIVE/DEMO existente. `i18n.js` lo cablea solo si
  encuentra `#lang-toggle` en la página; guarda la elección y dispara
  `document.dispatchEvent(new CustomEvent("akbal:locale-changed"))`.
- **Texto generado por JS** (`app.js`, `gps.js`, `globe.js`, etc.): se llama
  a `window.AkbalI18n.t("clave")` directamente donde se arma el string, y se
  puede escuchar `akbal:locale-changed` para re-renderizar si hace falta.

## Dónde está aplicado

- **Topbar** (compartido por `index.html`, `wifiradar.html`,
  `aircraft-radar.html`, `wardrive.html`, `gps.html`): nav completa, toggle
  LIVE/DEMO, popover de sistema, logout — mismas claves `topbar.*` en todas
  las páginas.
- **`index.html`** completo: chat, dispositivos USB, OST, Wifi Audit
  (pestaña `tab-wardrive`, incluye sus modales), Ajustes (las 6 subpestañas)
  y los modales sueltos (wifi-connect, image-preview, file manager).
- **`login.html`**: HUD, formulario, mensajes de error — incluye su propio
  selector de idioma (la página no tiene topbar, va fijo arriba al centro).
  `/i18n.js` e `/i18n/*.json` están en el allowlist de rutas públicas del
  servidor (`device/web-admin-server.ts`) para que funcionen sin sesión.
- **Modal de detalle de satélite GNSS** (`gps.html`, ver docs/gnss.md).

## Qué queda pendiente (deuda conocida, no bloqueante)

- Strings generados dinámicamente dentro de `app.js` (3700+ líneas: listas
  de dispositivos, estados de wifi/bluetooth, mensajes de chat, etc.),
  `wifiradar.js`, `aircraft-radar.js` y `wardrive.js` — la mayoría sigue
  hardcodeada en español. La infraestructura (`AkbalI18n.t()`) ya soporta
  migrarlos incrementalmente, archivo por archivo, sin tocar el motor.
- Body específico de `wifiradar.html`/`aircraft-radar.html`/`wardrive.html`
  más allá del topbar (toolbars, leyendas, modales propios de cada página).

## Agregar una clave nueva

1. Agregarla en `i18n/es.json` **y** `i18n/en.json` (mismo path anidado).
2. Etiquetar el HTML con `data-i18n="seccion.clave"` (o la variante
   `-placeholder`/`-title`/`-aria-label`/`-alt`/`-html` que corresponda), o
   llamar `AkbalI18n.t("seccion.clave")` desde JS.
3. No hace falta build: son archivos estáticos servidos tal cual.
